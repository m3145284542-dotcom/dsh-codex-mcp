# 适配本机工作方式的分工示例

这些是任务选择示例，不是所有任务都必须经历的固定流水线。用户最新要求优先；不要把曾经一次实验的要求推广成所有作业规则。

| 用户任务 | 可以交给 DeepSeek 的部分 | Codex 保留的部分 |
| --- | --- | --- |
| 批量整理几十份文件、从已有材料生成表格 | 在限定目录提取指定字段，附来源位置和缺失项；写入独立中间文件 | 定义字段，检查数量、单位、去重和代表性记录，再生成最终交付 |
| 修改代码、实现已经确定的模块 | 一个接口确定、文件归属清楚的模块；批量同类修改；指定命令的测试和失败分类 | 未确定的架构、共享接口、集成冲突、最终差异和关键行为检查 |
| MATLAB / Simulink 项目或报告 | 明确公式对应的程序、独立参数扫描脚本、已有仿真结果的整理、基于真实材料的正文草稿 | 核实模型和参数；若实际运行/截图工具仅 Codex 可用，由 Codex 操作；确认输出对应真实运行，执行当前适用的课程规则 |
| 论文阅读、引用、科研写作 | 已取得材料的分段提取、术语表、实验信息表、受限范围的草稿或证据检索 | 科学论断、证据边界、文献/DOI核验、最终论证；有关专用 skill 的要求必须随任务转交 |
| Word、PPT、PDF 文档 | 大批素材整理、内容初稿、限定文件的生成或排版；前提是 worker 确实有需要的工具 | 指定模板、图片完整性、公式可编辑性等要求；最终渲染和目视验收，不把“生成文件”视为“版面通过” |
| 公众号文章 | 从给定素材提纲化、候选表达、长稿初稿；仅在工作量值得交接时 | 定位、作者语气、事实核验、标题取舍、最终稿和用户要求的排版；不因委派自动发布 |
| 再找一个模型检查方案 | 一个具体问题的独立检查，如找出该算法的边界情况 | 根据代码、数据和原文裁决分歧，不按多数投票决定正确性 |
| 一个错字、一行配置、简短问题 | 通常不委派 | 直接完成，避免交接比任务还长 |

## 交接时容易漏掉的本机约束

- Windows 路径使用绝对路径，工具参数优先结构化传入。不要要求 worker 执行只适用于 Bash 的命令。
- 不是所有 Codex 工具、登录连接或聊天附件都在 Harness 中可用。先给它实际可读取的本地材料；不要承诺它能访问未验证的服务。
- 结果要落到当前任务指定的输出目录。草稿、日志和测试文件放在 scratch/work 目录；不要把中间版当成最终文件交付。
- 发送完整的任务约束，不发送整段历史。前置技能中真正影响产物的要求可以指向 worker 可读的文件，必要时转述相关条款。
- 大文件和长日志可由 DeepSeek 读取并将详细结果存文件，只返回简短摘要、输出路径和异常，避免 Codex 再把全部材料读一遍。
- 长任务中记录 `session_id`、`cwd`、允许修改的路径、验收状态。接着改同一结果用 `dsh_resume`，换题才新建会话。

## 最小验收示例

给 worker 的目标是“从 30 份报告中提取参数”，则返回表格、每行的来源页码/段落和缺失项清单；Codex 检查输入文件数、表格记录数、字段单位及抽样原文。仅返回“已整理完”不能验收。

给 worker 的目标是“修复指定测试失败”，则限定文件和原始错误，要求解释原因、列出修改和实际测试结果。Codex 检查改动没有通过删测试、放宽断言或修改无关文件来掩盖问题，再按风险做针对性复验。
